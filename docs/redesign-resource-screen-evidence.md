## Shared evidence and notation

Source prefix: `app/src/main/kotlin/com/hcloudcontrol/`. Unit-test classes live under `app/src/test/kotlin/com/hcloudcontrol/`; network contract classes under `core/network/src/test/kotlin/com/hcloudcontrol/core/network/`.

- **Read**: existing `ui/state/SectionLoader.kt` and `HCloudReadSection`/`HCloudSectionState`; independent context-scoped reads, timestamped stale content, refresh and sanitized retry/missing/denied/offline states. S3 uses that same loader with `readS3Inventory`, verifying its exact selected S3 context and pinning credentials only inside a transient read closure, never routing through a Cloud repository. Typed S3 HTTP failures use the same sanitized classifier.
- **UI**: one `HCloudAppScaffold`; shared tabs, segmented controls, form fields/shell, dialogs, resource cards, menus and resource picker. Read-only cards omit click actions. `OperationReviewDialog` labels its checkbox row and starts typed identity/keyword blank and acknowledgements unchecked.
- **Operation**: one persisted `OperationCoordinator`, `OperationSession`, `OperationReviewDialog` and `OperationResultDialog`. Close is allowed by `record.canClose`, not read-busy state; terminal Close starts a new session attempt. Direct S3/SSH adapters use the same coordinator, not another operation state machine.
- **Navigation**: `RegisterResourceChildNavigation`/explicit S3 `RegisterChildNavigation`, hosted feature BackHandlers disabled, standalone fallback retained. Modal dialogs own their guarded dismissal. `rememberContextualResourceId`, typed public-draft savers, `DirtyFormExitPrompt`, and `rememberRestorableLazyListState` provide the corresponding scoped state.
- **Cross-cutting tests**: `SectionStateTest`, `ContextualResourceSelectionTest`, `ScrollPositionRegistryTest`, `DirtyFormExitGuardTest`, `CanonicalNavigationTest`, `OperationCoordinatorTest`, `OperationAttemptTest`, `OperationResultPolicyTest`, `CostPresentationTest`. They establish shared/pure behavior, **not rendered feature-screen acceptance**.

Test names in the table identify source evidence, not a claim that every UI variant has an automated test. Root owns all Gradle executions; consult [implementation progress](redesign-implementation-progress.md) for actual build/test/lint results. Newly added tests still require the next root verification snapshot when this document is written.

## Remaining acceptance work / limits

- Every row still needs real device visual/accessibility/gesture verification stated above. This map must not be used to close issues merely because a composable or unit-test class exists.
- Feature-composed tests for alias entry/Back, process recreation, partial reads, form discard, menu focus and operation dialogs are not comprehensive. Shared pure tests do not prove those rendered interactions.
- Unknown creation without a provider-returned immutable ID remains unresolved after diagnostic reads. Unknown metadata/rule/member changes without the complete durable original proof remain unknown; no automatic replay is offered. These conservative limits are explicit, not falsely reported as success.
- Removing an S3 profile preserves and exposes the original journal identity, but there is no UI to restore credentials under the removed original UUID. Such status is explicitly unavailable; adding another profile never silently rebinds it.
- Debug-only component fixtures already exist at `app/src/debug/kotlin/com/hcloudcontrol/ui/designsystem/HCloudComponentGallery.kt` with light/dark/200%-font previews. They are synthetic, not 106 feature-screen screenshot acceptance. Debug merged manifests include Compose `PreviewActivity`; runtime gallery launch has not been accepted by this worker, and no release gallery entry was added.

No issue was closed by this worker, no commit was created, and no Gradle command was launched independently of the root build owner.
